Conversation → controlled pilots

The goal is a tighter loop, not a larger stack.

The July 20 exchange points to one operating model: meetings create context, issues hold outcomes, previews make progress reviewable, and credentials grant agents authority without giving them custody of secrets. Each layer should be piloted independently so Brendan and the volunteer team stay in control.

Keep raw context private. Promote decisions and executable work only when they are ready for the team.

Four action lanes

One conversation, four different risk profiles. The first lane can begin without waiting on infrastructure.

01pilot first

Granola for meeting memory

Granola works with Teams by capturing local system audio. It stores transcript text and notes, not the completed audio recording. The important constraint: its automatic consent message currently supports Zoom on macOS—not Teams.

Next move

Ask the group for an explicit two-meeting pilot. Announce transcription manually at the start, keep notes private by default, and agree a transcript-retention period before the first meeting.

02design the loop

GitHub Projects as shared agent context

ghp already reads Project #26 live and produces compact issue bundles with comments, files, and cross-references. What it lacks versus the Linear loop is explicit start → journal → respond write behavior.

Next move

Keep Linear as Brendan’s private intake for now. Prototype a narrowly scoped GitHub journal command on one public-ready issue, with every write visible and reversible. Do not migrate the portal before that loop proves itself.

03security pilot

1Password for agent authority

The new 1Password Environments MCP for Codex does not return raw values through MCP, model context, terminal output, or disk. It injects approved variables into the target process for the task. That is materially narrower than granting a terminal session broad CLI access.

Next move

Evaluate it in a disposable environment with one low-risk credential. Require task-scoped approval, a named target process, and a check that stdout/logs cannot echo the value. Keep CLI + biometrics as the human-operated fallback.

04infra dependency

PR previews + Playwright CI

Portal V2 already has 68 passing local Playwright tests and a dispatch-only GitHub workflow. The workflow itself records the blocker: PR runs need a usable database. Current deployment targets main on a self-hosted runner.

Next move

Design the preview contract before wiring CI: one URL per PR, V2 and legacy reachable together, isolated or read-only test data, teardown on close, then Playwright pointed at that URL with failure-only evidence.

Recommended sequence

Fast learning first; expensive infrastructure only after its contract is clear.

Guardrails that keep humans in control

  • Every issue has one observable outcome and one current owner.
  • Every meeting begins with explicit disclosure and agreement.
  • Every agent write lands in a visible journal before state changes.
  • Every credential grant is scoped to a process, task, and short lifetime.
  • Every preview is disposable and posts its URL back to the PR.

Do not do yet

  • Silently transcribe Teams because no bot appears.
  • Dump raw transcripts into public GitHub comments.
  • Move the whole portal workflow from GitHub to Linear.
  • Give agents broad vault access as the default path.
  • Make Playwright required before previews and data are stable.
