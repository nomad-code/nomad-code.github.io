Linear · Nomad Code Harness

Reusable context for reading & writing the nomad-code Linear workspace from the CLI. Generated 2026-06-15.

TL;DR — Two paths. Read from the local cache with linear-mac (no auth, offline). Write (create issues, comment) via the GraphQL API with LINEAR_API_KEY_NC. Keep team/state IDs cached below so you skip discovery next time.

Secrets live in ~/.config/zsh/secrets.zsh, sourced from ~/.zshenv. Never echo the key value — source it and reference $LINEAR_API_KEY_NC.

● Read path — linear-mac (no API)

~/dev/fai/wip/linear-mac — reads Linear's Electron LevelDB cache at ~/Library/Application Support/Linear/IndexedDB/. No key, no network, no rate limits. The app need not be running.

cd ~/dev/fai/wip/linear-mac
npm run issues            # list all issues
npm run issue TODO-63     # one issue as JSON
npm run dump | jq '.[]'   # everything
npm run serve             # local HTTP server

Caveats: issue descriptions and comments live in a separate object store and mostly come back null — for those, use the API. Data can be stale until the app re-syncs.

● Write path — GraphQL API

Endpoint https://api.linear.app/graphql. Auth header is the raw key (no Bearer).

Discover viewer / org / teams:

source ~/.config/zsh/secrets.zsh
curl -s -X POST https://api.linear.app/graphql \
  -H "Authorization: $LINEAR_API_KEY_NC" \
  -H "Content-Type: application/json" \
  -d '{"query":"{ viewer{name email} organization{name urlKey} teams{nodes{id key name}} }"}' | jq .

Comment on an issue (jq-escape the body so newlines/markdown survive):

PAYLOAD=$(jq -n --arg b "$BODY" '{
  query:"mutation($id:String!,$body:String!){ commentCreate(input:{issueId:$id, body:$body}){ success comment{ id url } } }",
  variables:{ id:"<issue-UUID>", body:$b }
}')
curl -s -X POST https://api.linear.app/graphql \
  -H "Authorization: $LINEAR_API_KEY_NC" -H "Content-Type: application/json" \
  -d "$PAYLOAD" | jq .

issueId accepts the UUID (from a fetch) — the human key like TODO-63 works for issue(id:) reads but use the UUID for mutations.

Create an issue:

mutation { issueCreate(input:{
  teamId:"47d8ea75-fb1c-467c-9941-3951593bfdf2",   # TODO
  title:"...", description:"...",
  stateId:"96d840ef-a27d-4593-b005-7beaa6d94a1e"   # Backlog
}){ success issue{ identifier url } } }
