Timezone contract

instant_utcThe true point in time.
wall_clockThe clock seen where the activity was captured; archive fake-Z is never converted as UTC.
captured offsetThe authority for reconstructing that wall clock.
zone nameReported provenance, not verified geography. A named rule set may exist without being the correct location.
OmarKeep +07:00. It preserves the source 09:50 wall time for the verified Apple Health → Omar sample. GMT/UTC would break new no-GPS uploads.
live nuanceThe newest archive record reports Africa/Addis_Ababa at +03:00 while workout context is Sofia. The offset math is correct; the zone identity is not promoted to fact.

API gaps

  • Default Strava quotas constrain both 15-minute and daily traffic.
  • Uploads are asynchronous and normalized after polling.
  • No general documented public delete or media-upload surface.
  • Hidden start times can return as 00:00:01.
  • Local v3 compatibility lacks writes, zones, social objects, routes, clubs, gears, and webhooks.

Vibe gaps

  • A feed card is not the memory of the session.
  • Strength sets can travel; intent, confidence, corrections, and voice context usually cannot.
  • Visibility settings are not the same thing as a deliberate redaction contract.
  • A hosted link should be a projection of the local record, not the only surviving record.

What now exists

  • /external explains the topology and renders the live archive time audit.
  • /api/fit/v1 exposes native activity, capabilities, and time-audit routes.
  • /share/activities/<id> and ?view=share provide a redacted outward surface.
  • npm run export:outward produced the complete 26 MB local cloud-input bundle as draft; nothing was published.
  • The FIT UI is branded FIT, while Strava is explicitly an adapter and third-party host.
