The BPO answer:
six planes, one constitution

Do not build a Portal clone. Build the thinnest sovereign control plane that joins the pieces you already proved.

01 · FAMILYBrand kernel

Voice, Grove, proof standard, privacy laws, closeout grammar. Shared by every agent and artifact.

02 · MEMORYContext compiler

Typed route → ordered files, prior decisions, dependencies, budget, freshness, capability envelope.

03 · ACTIONSession runtime

Harness, model, host, repo, isolated worktree, lease, permissions, cost, live status.

04 · FLOWLinear journal

Outcome, state, owner, prompt, plan, response. Workflow never impersonates semantic truth.

05 · PROOFGit + artifact

Durable decision, code, provenance, screenshot, readable synthesis. Promote outcomes, not transcripts.

06 · LEARNINGEvaluation

Reuse, rework, context misses, stale facts, token reconstruction, merge conflict, human correction.

BPO has an architecture. It does not yet have a single operable product surface.
That is the gap XIRP makes obvious.

You can reconstruct the system from seven tickets, several scripts, multiple artifacts, and your own memory. A new agent cannot. The next milestone is not more ontology. It is a compiler + registry + cockpit that makes the ontology executable.

What to do better

Ranked by compounding value, not novelty.

01

Compile context; stop “letting agents browse”

Add scripts/route / bpoctl context ROUTE. Return a deterministic manifest: world, ordered reads, decision hashes, workflow link, capabilities, exclusions, token estimate, freshness. Exact first; fuzzy only as fallback.

02

Create one append-only session registry

Normalize task ID, route, harness, model, host, repo, worktree, owner, lease, start/end, parent/fork, artifact, cost, outcome hash. This becomes the source for a local command-center view.

03

Make worktree-per-session the default

Your host-level lease prevents split brain, but XIRP's sharper unit is the session. Spawn an isolated worktree, bind it to TODO + route + agent, and require a merge/handoff receipt before release.

04

Distill automatically; publish deliberately

At wrap, propose decision diffs, stale-doc repairs, route additions, and reusable instructions. A human or policy gate promotes them to Git. Never pour raw transcripts into the knowledge base.

05

Measure context quality, not output volume

Track rediscovery tokens, duplicate attempts, stale inputs, human corrections, failed handoffs, context reuse, and time-to-first-valid-action. “More PRs” without lower rework is entropy.

06

Generate a world catalog from truth

Build the Backstage-like layer as a projection: repos, projects, owners, machines, dependencies, policies, data sensitivity, active tasks. Generate it from Git; never hand-maintain a second ontology.

07

Codify the brand kernel

Create a small versioned agent constitution: voice, visual tokens, privacy boundaries, escalation rules, artifact/evidence contract, and human-control policy. Agents inherit it; souls extend it.

08

Build a cockpit only after the contracts

A local static/Web UI should show live sessions, leases, worktrees, costs, blockers, stale context, handoffs, and artifacts. The UI reads the registry; it does not become truth.

Go-ham sequence:
30 / 60 / 90

The first 30 days should make the architecture executable. The next 60 make it legible and compounding.

See the whole fleet

  1. Render local command-center artifact from the ledger.
  2. Add session spawn, park, resume, wrap, handoff.
  3. Show conflict risk and ownership before dispatch.
  4. Add context freshness + budget report.
  5. Instrument rework and rediscovery.
61–90 DAYS · COMPOUNDING

Make sessions improve the system

  1. Generate proposed docs/decision diffs at wrap.
  2. Build curated skill/rule catalog without MCP sprawl.
  3. Route tasks by capability, cost, and trust tier.
  4. Compare models on the same bounded work packet.
  5. Graduate proven patterns across worlds—never souls.

Steal the mechanics, not the dependency

XIRP is validation and a design reference—not a reason to make Portal the owner of your life.

Steal aggressively

  • Worktree isolation per concurrent session.
  • Model/harness switching without reconstructing context.
  • One registry for sessions, owners, work items, and resume points.
  • Organization/world catalog injected at session start.
  • Wrap-time knowledge capture and reusable rule discovery.
  • Start with one team and one project; prove reuse before scale.

Do not import blindly

  • Portal as a second semantic truth store.
  • Raw transcripts promoted as “institutional memory.”
  • Automatic documentation writes without review or provenance.
  • One global context pool across BPO, BOB, BRE, and client worlds.
  • Marketplace/MCP surface area before repeated pain earns it.
  • Parallel agents without leases, isolated worktrees, and merge receipts.
