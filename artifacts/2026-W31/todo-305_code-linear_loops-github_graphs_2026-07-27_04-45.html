linear loops · github graphs

Pressure test of the thesis: Linear URL as loop context, GitHub repo as graph context — hand any harness a repo clone and a Linear API key and it has everything it needs. Outcome claim: three worlds (Found·TECH, Nomad·TODO, Dhamma·DHA) run from an iPhone with Linear iOS and GitHub iOS.

Verdict — survives, with one amendment

The loop/graph split is real and this session proved the minimal contract cold. But the formula is three-legged, not two: the repo is the graph, the Linear key is the loop, and the quietly assumed third primitive is a runner — something that ignites a session when the phone writes a prompt. "All you gave me" included a running harness.

Pressure points

P1

The trigger gap

structural

Repo + key is everything the agent needs once running. Nothing in either surface ignites the loop; the phone can write a prompt but cannot start a session. The runner (this remote harness, hooks, PR subscriptions) is unpriced infrastructure the thesis treats as free.

P2

Live-URL contract vs. branch discipline

observed live

The loop's step 4 says share an artifact URL only after it returns 200. In a branch-and-PR world (this session), the artifact cannot be live until merge — so the respond step must hand over a PR instead of a page. The desktop Stop-hook-to-main path and the remote PR path obey different contracts.

P3

Hooks are harness-shaped

degrades

The automation — auto-file, gate injection, provenance, auto-close — lives in .claude/ Stop hooks. The scripts are harness-neutral; the hooks are not. On codex, gemini, or pi the protocol degrades to "remember to do it by hand," and AGENT.md already logs two artifacts shipped broken exactly there.

P4

Secrets live outside the graph

already failed once

The graph is self-describing; the credentials are not. Key routing already failed once — a generic key silently hit the wrong workspace — and the fix (world-pinned env names) lives in a zsh file no repo carries. Every new machine or container needs out-of-band provisioning.

P5

No locking on the loop

at scale

Comments are append-only, so the journal is race-safe. But start blanks the description and state transitions aren't transactional: two harnesses on one ticket can double-archive or fight over state. Fine for one human; a contended lock with no lock at company scale.

P6

Privacy gradient is prose, not enforcement

amplified by mobile

Three worlds, three keys, tiering rules written in markdown plus one tripwire CI. One wrong respond posts private content to a public surface. Phone-speed control amplifies exactly this failure: taps are faster than the guardrails are strong.

Amended formula

graph (repo) + loop (Linear key) + runner (trigger)

The outcome claim stands for read, write, and approve — those surfaces exist on the phone today. What the phone cannot yet do is start the machine, and remote sessions with PR subscriptions are precisely that third leg arriving. The next engineering target isn't more loop or more graph: it's making ignition a first-class, named primitive instead of ambient infrastructure.

The sentence — device grammar (rev 2)

Refinement from the phone: the Linear iOS create sheet's two buttons are the architecture's two nouns — Issue = task = loop, Project = repo = graph (a projection, not an isomorphism: a Project is workflow and completes; a repo is truth and accumulates). And the verb isn't missing — it's hardware-resident. The full sentence:
