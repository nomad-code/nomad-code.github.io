platform: the shell is done, the clients aren't

The "many clients, one shell" you're aiming for — the Codex / Claude-desktop-iOS harness shape — is already half-built in found-ai/platform. The shell converged. What's missing is that the client is a compile-time constant, not a runtime value.

converged

One shell, empirically

AppShell replaced the four-variant ShellSwitch dispatch (TECH-728: "delete the variant flag — one deploy, one design"). The many-shells experiment ran and was collapsed. Residue: two misnamed variant CSS files still globally imported.

contract

Client bundle spec

Per-client manifest (slug, source sha, artifacts + sha256, chat allowlist, enabled_core_tabs, client_surfaces), zod-validated loaders, fail-closed for unconfigured clients. The hard contract work most teams never do is done.

the gap

Client baked at build

NEXT_PUBLIC_CLIENT_SLUG is a Docker build ARG, re-read in six places with the same hardcoded fallback. No /[client]/ route, no session client, no switcher. One image = one client.

That last row is the real decision hiding in the aspiration: making the client a runtime value contradicts the written security thesis that "partner A cannot touch partner B's data" should be an IAM policy, not app-layer trust. Runtime clients vs per-service isolation is a security-posture choice, not a refactor. (Middle path exists: keep one service per client but resolve the slug from the lane's env at runtime, killing the build-time bake without weakening isolation.)

where the monorepo pressure actually is

loudest pain

The fai-x import ritual

Upstream chat engine is copied in as reviewed source snapshots with a hand-maintained divergence ledger — three imports in two weeks, and one refused because upstream moved to pnpm. This is a package boundary emulated by a human with a changelog.

data path

Client repos synced by script

Each client pipeline is its own repo; a sync script commits ~5MB of JSON into the app repo. Bundles are the reusability seam, but the seam crosses repos by hand.

ready to split

Packages already visible

src/lib/{bundle, chat, query, engine, log} and components/legos are cohesive, tested units — packages/* waiting on a git mv. Only one path alias today (@/*).

tooling

Scripts pre-factored

Seed/sync/verify CLIs already split pure lib from CLI entry, run with type-stripping, no build step — a tooling package in embryo.

cheapest-first sequence (candidate, pre-Rob-alignment)

  1. Collapse the six slug reads into one resolver in a bundle package; drop the Docker ARG in favor of runtime env. Smallest change, kills the most duplication.
  2. Bring the chat engine inside the wall as a package; delete the divergence ledger. The import ritual becomes an import statement.
  3. Make enabled_core_tabs drive the nav — the shell only truly hosts many clients when the manifest controls the surfaces.
  4. Then decide the runtime-client question with the security thesis on the table.

Steps 1–3 are all compatible with either answer to step 4 — no regret moves.
