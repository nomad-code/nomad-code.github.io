The handoff rail

“Teleport” means a recoverable work-state transition—not pretending process memory can cross two kernels.

1

Prepare

Capture tracked, staged, unstaged, and untracked work through a temporary Git index. The source branch and index do not move.

2

Record

Push an epoch-named GitHub handoff ref as the durable checkpoint and coordination record.

3

Carry

Send a minimal incremental Git bundle over verified Tailscale/SSH. Headless Keychain access is not required.

4

Recreate

Build an isolated ~/dev/teleport/<task>/<epoch> worktree on the target.

5

Own

Only after confirmation and a safe source state does the target Claude launch from the reviewed handoff brief.

Hard boundaries

The supervisor treats convenience as subordinate to recoverability and world separation.

◉

Unmanaged means untouched

Existing tmux panes are observed only. No terminal scraping, keystroke injection, or broad process kills.

◇

BPO ≠ BOB

TODO/FEM/ELE/PASS remain personal-world; TECH remains Found-world. Tokens and state are selected independently.

↯

No secret-shaped cargo

No credentials, ignored files, process memory, raw transcripts, or prompt body enter the capsule manifest or artifact.

What still does not “teleport”?
A live tmux process and Claude’s in-memory context remain on their source Mac. The target starts a fresh Claude from the exact Git snapshot plus reviewed handoff brief. Native Claude Remote Control remains an optional escape hatch, but identity tokens, custom endpoints, and Headroom can make it unavailable; the supervisor does not depend on it.
