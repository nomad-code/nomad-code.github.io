Pinch points

What actually blocked the i17pm → M5 lane.

M5 unreachable

Online only via DERP relay; tailscale ssh, direct ssh, and keyed ssh all timed out. Every downstream step (creds, worker) is blocked on this.

Creds unconfirmed

Taildrop is fire-and-forget: no receipt. A credential transfer with no verification step must be treated as failed.

Wrong host assumption

The iPhone was steering tasks on M3, not M5. Runtime identity was inferred, not resolved.

Truth by prior mention

fleet.md became "the" M5 doc because it already mentioned M5. Deterministic routing without typed edges institutionalizes such accidents.

Architecture verdict

The 4-layer ports-and-adapters stack is sound; semantic routing wraps it as an addressing envelope. Slugs stay aliases — they resolve into typed route objects.

Capability ports

Control plane

Provider adapters

Linear · GitHub Issues · Forgejo · GitHub · GCP · Slack · Drive …

world is mandatory

ResourceRef without world lets a Found id and a BPO id collide across the privacy boundary. world: "bpo" | "found" | "dhamma" — identity, not metadata.

Capability ≠ identity

A GitHub PR reached via Tasks and via Code must stay one resource. Drop capability from ResourceRef; keep ExecutionRef separate (host, taskId, lane).

Gateway was a junk drawer

Split it: routing/policy/identity → control plane; auth/retries/rate limits → adapter transport; normalization → port boundary.

Feature negotiation

Linear initiatives ≠ GitHub milestones ≠ Jira epics. Ports need supported-feature discovery or explicit UnsupportedCapability — never silent CRUD reduction.
